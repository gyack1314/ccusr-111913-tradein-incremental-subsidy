# 业务分析方法与办案口径

本文件说明 `audit/` 应用如何把原始申报走到效果解释、方案审阅与结项调整。全部资料为本地合成数据，
规则来自 `data/rules.jsonl` 与 `docs/input-contract.md`，不代表真实政策或已公布补助公式。

## 1. 事实核验（audit/eligibility.py）

申报单位为一台旧机，须同时具备三个 **confirmed** 事实：购新 `new_order`、交旧 `old_receipt`、
规范处理 `processing`。

- `cancelled` 事实否决对应资格；`pending` 不构成完成回收，先预约未交旧不算完成回收。
- 部分退款（`refund_cents>0`）只登记 `PARTIAL_REFUND_NOTE`，不自动取消；若事实同时被取消，
  由 `CANCELLED` 否决。
- 资格边界：品类须在片区 `eligible_categories` 内，事实发生日不得早于 `actual_start`
  （原定启用日不构成资格）。
- 处理成熟：`processing` 为 pending 时，以处理发生日 + `grace_days` 为成熟日。观察时点在成熟日
  之前为 **未成熟（IMMATURE）暂缓**；过成熟日仍未确认则否决。未成熟不给确定零，可补交回执转正。
- 所有判断基于 `Materials` 的 `as_of` 快照：`known_at` 晚于观察时点的记录不可见，旧结项可按当时
  证据复现。

## 2. 同物身份（显式序列号 + 已确认审核）

归并只有两条合法依据，并以并查集实现：

1. 申报携带相同的显式 `old_serial`（硬证据）；
2. `identity_reviews` 中 `status=confirmed` 且 `same_device=true` 的审核。

名称相似不归并；`status=submitted` 的审核（如 I2）只登记为未决争议，不自动合并。

每个同物组最多产出 **1 台**补助。组内多份事实合格的申报形成竞争：

- 未裁决：该台不进入任何商户的确定上界，仅在整体上界保留每组合法 1 台，状态为暂缓。
- 后到的 confirmed 审核（如 I1 在 10/2 才确认 A006=A013）会暴露原先未发现的重叠，组的归并依据
  同时列出序列号与审核身份，不保留“先导入先得”。
- 裁决通过事件存储留痕；已有不同裁决不能覆盖，只能走更正事件。

## 3. 净新增效果识别（audit/effects.py）

目标人群是**居民来源片区**（`resident_region`）在观察窗内**所有渠道**的人均规范处理量，
不以商户所在地替代居民来源。渠道量只在相同人群与统计期比较。

| 分析 | 作用 |
| --- | --- |
| 多期 TWFE（区域+月份固定效应） | 主估计；处理组外的启用片区邻区从干净对照中剔除，外溢另做诊断 |
| 事件研究 | 启用前 -4..-2 月系数做平行趋势安慰剂诊断；显著偏离则 TWFE 不可直接当因果 |
| 分渠道 TWFE | campaign/ordinary/mobile 分别估计；仅活动渠道上升而其他下降指向渠道迁移 |
| 时间替代诊断 | 比较启用后首月与次月超额；次月明显回落（fade_ratio 高）表示提前了下月回收 |
| 邻区外溢诊断 | 邻居已启用而本区未启用月份的人均超额，识别跨区吸引 |
| 不完整月界分析 | 2026-09 ordinary 渠道 `complete=false` 不补零：下界按 0 台、上界按同片区同渠道历史最高月，区间宽度即不可识别部分 |

识别假设（平行趋势、SUTVA 松弛、TWFE 异质性处理效应负权重风险、不完整月处理）与不可识别范围
随每次分析输出，公开可查。制度不要求固定因果算法，本实现可替换；独立时期只用于诊断，不强求正面
结论。

## 4. 补助联合可行域（audit/funding.py）

单台补助受四个条件联合约束，**单项上界不能直接相加当全体补助**：

1. 真实合格台数（同物组按 1 台、未成熟不计入当前上界）；
2. 核定单价上限 `per_verified_unit_cents`；
3. 整体预算 `program_budget_cents`（预算 ÷ 单价 = 预算可容台数）；
4. 有依据的净新增上界（取界分析上界，缺界时取点估计换算台数）。

联合上界 = min(合格台数上界, 预算可容台数, 效果证据上界)，整体下界为 0。

- 商户申报量是各自上限，**不是贡献权重**。商户净新增贡献无法从全区效果分开时，不按核销量比例
  编造增量；`max_feasible_allocation` 先用 LP 证明联合上界可达，再用确定性轮询给一个均衡的行政
  分配，并复核可行性。分配是可行域内的行政安排，不是商户因果增量。
- `check_allocation` 校验待审人员的替代方案是否同时满足商户上界（无争议台数 + 已裁决同物组）、
  联合上界与预算，违例逐条列出。
- 效果未知部分按 `unknown_effect_policy` 暂缓，不强制分摊。

## 5. 办案事件与结项调整（audit/cases.py）

本地事件溯源存储（JSONL，只追加）：

- `receipt_supplement`：补交处理回执，回执须有稳定 `receipt_id`；同事实同身份幂等，不同身份拒绝
  覆盖。可先经独立回执服务（`audit/receipt_client.py`）核对投递事实与摘要，断连后转 GET 复核。
- `identity_ruling`：同物裁决，保留全部原申报来历；不同改判须走更正。
- `plan_accepted`：接受整体方案时比对方案依据指纹与当前资料指纹；资料或预算已变动则标记
  `basis_changed` 并列出受影响依据。
- `disbursement`：已确认发放只记本地回执，金额必须为正，按 receipt_id 幂等；**已发金额不可删除
  或改写**。
- `correction`：更正只追加，`payable_more`（待补足）/ `recoverable`（待追查）分列，台账折叠时
  已发金额始终保留。

`trace` 可逐笔追到某商户金额为何可发或暂缓：每个事件带观察时点与资料快照指纹，旧结项按当时
`as_of` 仍能解释；当前分析则区分真实新增、渠道迁移、未成熟处理与仍有争议的补助。

## 6. 输出口径区分

分析报告中的四类口径不可混用：

- **真实新增**：效果识别支持的全区净新增区间（含界分析）。
- **渠道间迁移**：分渠道与外溢诊断暴露的替代/吸引部分。
- **未成熟处理**：grace 窗内 pending，暂缓且不给确定零。
- **仍有争议的补助**：未裁决同物组，组上限 1 台但归属未定。
